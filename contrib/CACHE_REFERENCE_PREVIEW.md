# 缓存引用只读预览

`cache_reference_preview.py` 是独立标准库工具，仅对 [离线迁移工具](OFFLINE_MIGRATION.md) 生成的完整、尚未投入使用的包做观察。它没有 `--apply`、隔离、移动、删除或自动清理入口；不改运行插件与 Web 的行为。不要对真实运行中的数据库或缓存使用该工具，也不要把观察结果交给删除脚本。

```bash
python3 contrib/cache_reference_preview.py /absolute/persistent/archive-copy
```

默认输出 JSON 元数据：缓存文件名/大小、状态、按类别去重的引用记录数，以及不确定性计数。正文、JSON 内容、用户身份、消息 ID 和 SQLite 错误载荷不输出；文件名本身可能是私人元数据，报告按归档保护。超时默认 300 秒，可用 `--timeout-seconds` 调整。

## 覆盖的观察范围

- 正常 `chat_history` 记录的字符串字段，含序列化后的合并转发缩进内容，以及嵌套 JSON 对象/数组。
- `archive_trash.row_json` 的完整记录载荷，含其中的消息、嵌套内容及其他字符串字段。
- 已落盘 `chat_archive_failed_writes.jsonl` 的公共格式记录（8/12 字段 tuple 转 JSON list），包括消息和其他字符串字段；不自动重放。
- `session_stats` 的派生字符串字段，用于保守保护仍显示的缓存路径。它可能与正常消息重复，不能把各类别的和当作真实拥有者数量。

识别完整 `/static/cache/<文件名>` 路径，处理 CQ/HTML 编码、百分号编码和 CQ JSON 的结构解析。每条记录内，同一个文件只计一次。正文或外部 URL 中出现同样路径也可能被保守计入；观察不是精确所有权引用计数。JSON 里的 `filename: "x.png"` 本身不当作已证实的本地路径，也不会据此推断它无引用，而会报告歧义。

损坏/未知格式的回收站或失败记录、仅文件名的元数据、未解析 CQ JSON、其他数据库表/状态条目、二进制字段、深度/大小/节点上限，以及不支持的本地路径都会形成明确警告。编码最多逐层展开三次，结构深度 24、节点 20000、单字段或失败队列记录 4 MiB；超过限制不声称扫描完整。

## 文件与并发边界

只在包的受控 `data/web_cache/` 目录观察直接子项；普通文件须使用简单文件名。子目录/不支持的条目保留并标记，`.tmp` 保留为临时状态。包的路径/符号链接/硬链接/特殊文件校验沿用离线工具；路径穿越或编码斜杠不解析为缓存文件。不会读取缓存媒体内容来做识别或下载媒体。

扫描前后重新验证整个包的清单/哈希，变更会拒绝输出该次观察。SQLite 打开的引用扫描库是临时主库副本，校验未使用的规范化库采用 immutable 只读方式，避免创建 WAL/SHM。临时副本结束后清理；包和缓存没有移动操作。并发新增消息、回收站/状态或文件变更通常会被验证发现，但该检查不是跨数据库/文件系统的原子锁，也不承诺在线扫描一致性。

`no_reference_observed_in_supported_snapshot_fields` 只表示该文件在上述支持字段的快照中未观察到路径。`no_reference_observed_bytes` 不是可回收空间。即使没有警告，输出始终为 `reclamation_authorized: false`、`delete_or_quarantine_enabled: false`、`in_memory_queue_or_downloads_checked: false`。工具不证明维护者已停止所有写入，不扫描内存队列、下载中的对象、外部备份或未知未来格式；这些文件全部保留。

## 为什么本轮没有回收或可恢复隔离

公共实现中，`media_cache.py` 先把下载完成的文件重命名到最终缓存路径，`main.py` 才把带该路径的记录送入 `batch_writer.py` 的队列。两者之间、入库前的缓冲期间，文件可以没有数据库引用，但已经被待写消息使用。下载锁只覆盖同 URL 的下载，SQLite 写事务不能同时锁住这段文件发布与排队过程。

独立 Web 的恢复/管理操作、插件入库器、不同进程以及现有按时间清理，也没有统一的跨进程附件生命周期协调。把“零数据库引用”文件移动到隔离目录同样可能让随后入库的新引用失效；可恢复不代表并发安全。

真正回收前需要公开、完整的 pending/committed 引用生命周期与共享协调：媒体发布前登记待写引用、失败/取消/队列落盘与重放的状态、入库提交、回收站恢复、进程间互斥或可验证的停写，以及隔离后新增引用的恢复协议。这些条件尚未落实，本轮不提供自动删除来绕过它们。此预览不等于记者期望的同步引用计数附件回收，issue #4 的该部分继续开放。SQLite 文件缩小/安全擦除也不由本工具承诺。

## 合成回归

`python3 -m unittest discover -s tests -p test_cache_reference_preview.py -v`。测试仅使用临时合成数据库和媒体，覆盖正常/回收站/嵌套/队列共享引用、编码和文件名歧义、未知格式、路径/链接、并发新引用与缓存变更、CLI 只读及正文不外露、资源上限和完整文件保留。其他部署策略保持独立：PR9 启动阻止策略仍未合并，真实 Docker 升级复现不属于这些离线观察。
