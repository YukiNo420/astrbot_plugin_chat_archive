# 离线归档复制与迁移

`archive_migrate.py` 是独立标准库工具，不导入 AstrBot，不修改默认保存位置或启动流程。它帮助维护者在升级或切换数据位置之前生成可检查的副本。源目录完整保留；工具不修改运行实例的环境变量、配置或服务，不自动切换。PR9 的非空旧目录阻止启动策略不属于本工具。

## 停写前提

实际复制前，维护者必须停止此归档的全部写入来源：插件消息接收、批量写入器、媒体下载/缓存清理、消息管理/保留任务以及独立 Web 写入。等待进行中的操作结束，正常排空内存队列并确认退出；只停止 Web 或只暂时没有 QQ 消息不够。整个复制、校验、切换过程须保持停写。

工具要求 `--confirm-stopped`，该参数是维护者声明，不会强行停服务，也不能证明所有写入器已关闭。复制前后文件身份、大小、时间与 SHA-256 比较，以及最后的短暂静默窗口，用于发现误启动/并发变化；它们不能代替停写或保证在线数据库、附件和队列之间的整体一致性。内存中的消息和未完成下载无法由文件复制补回。

仅支持可信、本机 POSIX 文件系统（Linux/macOS），不支持网络文件系统、符号链接路径/条目、硬链接文件、FIFO/其他特殊文件或被其他人同时重命名的目录。Mac 上应使用实际路径，避免 `/tmp` 等符号链接入口。单个选定 SQLite 文件须位于源数据目录；目录外自定义数据库需要单独设计一致性方案，工具明确拒绝猜测它的位置。虚拟表数据库当前拒绝迁移。目录嵌套上限 100 层。

## 默认预览与实际复制

先确认**实际**数据目录、数据库文件名和缓存位置。不要把整个插件源码目录当作数据目录；不要在备份完成前更新/重装仍把数据放在插件目录内的实例。选择插件安装目录之外、不会被升级覆盖的持久目录，并事先创建目标父目录。目标包目录必须不存在；即使已有空目录也拒绝覆盖。

```bash
# 默认只读预览，不创建目标、不打开原 SQLite 数据库
python3 contrib/archive_migrate.py /absolute/old-data /absolute/persistent/archive-copy

# 维护者完成上述停写检查后，才显式复制
python3 contrib/archive_migrate.py /absolute/old-data /absolute/persistent/archive-copy \
  --apply --confirm-stopped

# 在切换之前，保持停写，对尚未使用的完整包再次做只读校验
python3 contrib/archive_migrate.py --verify /absolute/persistent/archive-copy
```

默认数据库名为 `chat_history.db`。其他名称用 `--database-name 'custom database.db'` 指定，不接受目录外路径。超时默认 300 秒，可用 `--timeout-seconds` 调整。预览不打印正文或配置值，但路径和大小仍是本机元数据；输出与备份包须按私人归档保护。

工具先检查约 `3 × 源目录文件逻辑大小 + 64 MiB` 的可用空间，这是估计而非空间预留。其他进程仍可能耗尽磁盘；复制失败时保留源数据并拒绝将目标标记为可用。新目录权限为 0700、复制文件与清单为 0600，文件修改时间保留；不复制原所有者、ACL 或扩展属性。

## 包内容与一致性检查

完整包包含：

- `snapshot/`：整个旧数据目录的原始逐字节快照，包括数据库、现有 `-wal`/`-shm`/`-journal`、缓存、失败写入队列文件、空目录和未知状态文件。原始快照不直接交给 SQLite 打开。
- `data/`：缓存和状态文件副本，以及从临时数据库副本通过 [SQLite backup API](https://www.sqlite.org/backup.html) 生成的规范化数据库。选定数据库的 WAL/SHM 不作为运行库的一部分复制；已提交 WAL 记录已纳入数据库。SQLite WAL 的持久状态不能只由主 `.db` 文件代表，见 [SQLite WAL 文档](https://www.sqlite.org/wal.html)。
- `READY.json`：完成标记、各文件 SHA-256/大小、SQLite schema 摘要、每张表的行数和完整行内容摘要。会执行 integrity_check，并比较副本与规范化库的 schema、行数和内容；检查覆盖回收站、统计和其他普通表，不仅是聊天表。清单不是签名或防恶意篡改的证明。

临时 `work/` 仅在生成 SQLite backup 时使用，成功后清除；SQLite 只打开该副本与新运行库，不打开原库。任何复制、校验、超时、空间不足或中断失败都不移动/删除源文件。未完成目标保留 `INCOMPLETE.json`（极早中断时也可能只有空目录），没有可用完成状态；验证拒绝它，重试必须使用另一个不存在的目标。不要把残留 `data/` 配给运行实例。SIGKILL/断电可能留下部分文件；工具以标记和校验判定可用性，不承诺跨文件系统/损坏硬件的断电恢复。

失败写入文件仅复制保留，不自动重放、去重或合并。预览和复制均需读取全部源文件；大归档的内容校验可能较慢。该包不自动备份源目录之外的插件配置、密钥或自定义数据库。

## 显式切换与恢复边界

包验证成功后，维护者自行把插件和独立 Web 指向同一个 `archive-copy/data/`，并保留原配置位置与鉴权设置。已有绝对自定义数据库配置可能继续指向旧库，须同时核对 `ARCHIVE_DB_PATH`/`basic.db_path`；不能只修改缓存目录。例如为相关进程持久配置以下路径（按自己的真实位置修改）：

```bash
ARCHIVE_DATA_DIR=/absolute/persistent/archive-copy/data
ARCHIVE_DB_PATH=/absolute/persistent/archive-copy/data/chat_history.db
# 如需覆盖配置位置，ARCHIVE_CONFIG_PATH 继续指向原配置文件；工具不读取或改写它。
```

工具没有启动服务命令。维护者完成切换后，检查历史数量、会话/回收站统计、缓存访问及失败写入文件，再按自己的维护流程恢复接收。升级只发生在确认持久数据路径脱离插件目录之后；本工具本身没有修复所有默认路径选择或插件更新器行为。

**尚未有新写入时**，可以停住相关进程，恢复原路径配置继续使用完整保留的源目录；无需把包内文件逐个搬回。复制完成后若旧源目录又接收新写入，必须重新停写并生成新包，不能直接切换到过时副本。

**新目录已经写入后**，切回原库会丢失新消息、恢复/删除变更、队列或缓存状态。此时须先保留两边完整副本，再设计 ID 冲突、重复消息、回收站/统计及附件对账；本工具不做合并或自动回滚。`--verify` 校验包内文件；新运行库/状态新增写入后通常会判定包已变化，这不等于它已经损坏。它不校验原目录仍停写，也不许可忽略切换后的新增数据。

## 合成回归

`python3 -m unittest discover -s tests -p test_archive_migration.py -v` 只使用临时合成目录。涵盖未 checkpoint WAL、仅复制 `.db` 的漏数据对照、完整快照、缓存/队列、默认预览、目标冲突、路径/链接/特殊文件、低空间/ENOSPC、真实并发 SQLite 写入、并发工具目标竞争、损坏库、内容校验失败、超时/KeyboardInterrupt/SIGKILL、切换后新写入及原始数据保留。真实停写与路径切换仍由实例维护者执行。
